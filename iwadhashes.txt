# ZandroX downloadable IWAD hashes
# format-version: 1
#
# The exact builds of the free IWADs we will keep. This is the gate: a downloaded file whose header
# says IWAD is kept only if its SHA-256 appears below. Not its name -- its bytes.
#
# WHY THIS EXISTS ALONGSIDE iwadallowlist.txt
#
# The filename allowlist stops a server ASKING for doom2.wad. It cannot stop a mirror SERVING doom2.wad
# under the name freedoom2.wad, because a filename is a claim and the WAD header only says "this is a
# game", not which one. The hash is the only check a rename cannot walk past.
#
# The name list is still the pre-fetch early-out -- it stops us pulling 40 MB of something we would
# only delete, and transiently writing a commercial IWAD to disk is still downloading it. But the
# security boundary is here.
#
# WHY AN ALLOWLIST, WHEN ODAMEX USES A HASH DENYLIST
#
# Because the commercial set is not finite. doom2.wad alone shipped as 1.666, 1.666g, 1.7, 1.7a, 1.8,
# 1.9, a French build, BFG Edition and the 2024 KEX re-release; TNT shipped a bug-fixed second
# version; and Doom-engine games are still being SOLD today -- Selaco, Beyond Sunset, Hedon. A denylist
# would have to enumerate every past version and stay ahead of every future release, and one miss
# means the file downloads. An allowlist never learns any of them: unknown bytes are refused whether
# they are Doom II 1.666 or a game that ships in 2030.
#
# The cost lands here instead, and we accept it: free IWADs have versions too, so each release needs a
# line. When one is missing the failure is loud and safe -- the download is refused, not accepted.
#
# SHA-256, not MD5. Chosen-prefix MD5 collisions are practical, and a crafted commercial IWAD
# colliding with a free one's digest would defeat the only check that stops it. (Odamex can use MD5
# because theirs is a denylist, where a collision merely refuses something harmless.)
#
# Compiled into the binary at build time by tools/gen-wadlists.cmake, which FAILS THE BUILD if a line
# names a file that is not in iwadallowlist.txt.
#
# One build per line:
#   <sha256>    <filename>    <what it is>
#
# Blank lines and lines starting with # are ignored. Hashes are compared case-insensitively.
#
# TO ADD A RELEASE
#
# Get the file from the project's OWN release page, never a WAD mirror -- hashing a mirror's copy and
# calling it canonical is circular, and the mirror is exactly what this defends against. Verify a
# published signature or checksum if the project offers one, then `sha256sum` the extracted IWAD.
# Note the provenance in your PR.
