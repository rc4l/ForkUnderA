# ZandroX downloadable IWADs -- which names, and which exact builds.
#
# Every IWAD is assumed commercial and refused; these are the exceptions. Why it works this way is in
# features/wad-download/README.md.
#
#   <filename> | <sha256> | <what it is>
#
# Pipe-separated. Case-insensitive. Blank lines and # ignored. One row per BUILD, so a filename
# appears as many times as we have vouched for versions of it.
#
# A hash of "-" means the name is allowed but no build has been vouched for, so it is NOT
# downloadable -- the name only saves us fetching 40 MB we would then delete. The gate is the hash: a
# file that will be loaded as a game is kept only if its SHA-256 is listed below. The name proves
# nothing on its own; a mirror can serve doom2.wad under any name it likes.
#
# Compiled into the binary, deliberately not a CVAR or a lump: a list anyone can append to is not a
# gate. Adding a line is a PR, which is the right friction for a claim about someone else's licence.
#
# TO ADD A NAME: the bar is that free redistribution is the author's stated, long-standing position --
# not "it's on an archive somewhere", and not "the demo is free". List every filename spelling
# wadsrc/static/iwadinfo.txt accepts, or the entry only half works.
#
# TO ADD A BUILD: get the file from the project's own release page, not a WAD mirror (hashing a
# mirror's copy and calling it canonical is circular). Verify a published signature or checksum if
# there is one, note the provenance in your PR, then sha256sum the extracted IWAD.
